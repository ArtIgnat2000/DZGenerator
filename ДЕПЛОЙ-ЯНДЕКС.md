# Переезд на Яндекс: деплой из Git и когда нужна база

Короткий ответ: **сайт можно разместить у Яндекса бесплатно уже сегодня, а база данных
понадобится позже и не вместо хостинга, а вместе с ним.** Это две разные задачи:

1. **Статический сайт** (генератор, страницы уроков, `.sb3`) — Яндекс раздаёт бесплатно
   через SourceCraft Sites или Object Storage с деплоем из Git.
2. **База данных** (личный кабинет, прогресс, сдача заданий) — отдельный серверный слой,
   его нельзя «приделать» к статике. Нужен Cloud Functions + база.

Ниже — что выбрать, что уже готово в репозитории и что делать по шагам.

## Что выбрать

| Вариант | Что даёт | Сколько стоит | Когда брать |
|---|---|---|---|
| **SourceCraft Sites** | `https://<орг>.sourcecraft.site/DZGenerator`, HTTPS сам, сайт обновляется после пуша в ветку | 0 ₽, без лимитов трафика | **сейчас** — перенос без риска и без карты |
| **Object Storage + свой домен** | `https://dz.вашдомен.ру`, HTTPS через Certificate Manager | ~0 ₽ при нашем объёме (см. ниже) | когда нужен свой адрес в письмах |
| **Managed PostgreSQL** | обычный Postgres, кластер, бэкапы | от ~1 700–2 000 ₽/мес за минимальный кластер | когда база реляционная и нужны отчёты |
| **YDB Serverless** | pay-per-request база без простоя | 1 млн запросов и 1 ГБ в месяц бесплатно | для кабинета на десятки учеников — дешевле всего |

Порядок: **SourceCraft Sites → свой домен на Object Storage → (только потом) база.**

Запасной вариант публикации: ветка `release`. Если зеркало GitHub → SourceCraft не успевает
за правками, сайт можно собирать из ветки `release` того же репозитория, а `.sourcecraft/sites.yaml`
переключить на `ref: "release"`. В этом режиме содержимое сайта всегда равно `main`; подробности —
раздел 1, «Вариант Б».

### Почему не «просто база на хостинге»

Сейчас `V-labs-generator.html` — один файл без API, все данные в `localStorage`.
Это осознанное правило проекта (README, правило 6). База ничего не даст, пока
у ученика нет личного кабинета: писать в неё некому и читать некому.
Поэтому база — следующий этап (см. раздел «Когда понадобится база»), а не
часть переезда.

## Стоимость на нашем объёме

Сайт целиком — около 6 МБ (`V-labs-generator.html` 0,7 МБ, `lessons/` 1,8 МБ
со всеми `.sb3` и кадрами).

| Ресурс | Нетарифицируемый объём в месяц | Наш расход |
|---|---|---|
| Object Storage: хранение | первый 1 ГБ | ~6 МБ |
| Object Storage: GET/HEAD | первые 100 000 операций | десятки тысяч при активном классе |
| Object Storage: исходящий трафик | первые 100 ГБ | сотни МБ |
| Certificate Manager (Let's Encrypt) | не тарифицируется | — |
| Cloud Functions (если дойдём до кабинета) | 1 млн вызовов, 10 ГБ·час | сотни вызовов |
| YDB Serverless | 1 млн Request Units, 1 ГБ | тысячи RU |

Итог: **статический сайт со своим доменом и HTTPS ≈ 0 ₽/мес** (платить придётся только
за сам домен у регистратора), а серверная часть укладывается в free tier до
нескольких сотен активных учеников. Платная начинается с Managed PostgreSQL —
это осознанный выбор в пользу «обычного Postgres», а не необходимость.

## Что сделать в этом репозитории, чтобы варианты заработали

Уже добавлено:

Что нужно от вас (по одному действию на вариант):

2. Свой домен: завести бакет `dz.example.ru`, сервисный аккаунт и три секрета

## 1. SourceCraft Sites (бесплатно, 15 минут)

Сайт SourceCraft Sites публикует статику из **публичного** репозитория **публичной**
организации. Репозиторий `ArtIgnat2000/DZGenerator` публичный — подходит как есть.

1. Зарегистрируйтесь на <https://sourcecraft.dev> под Яндекс ID, создайте
   организацию (слаг латиницей, он попадёт в адрес).
2. **Создать репозиторий → Мигрировать существующий → GitHub** (или «Repository by URL»
   со ссылкой `https://github.com/ArtIgnat2000/DZGenerator.git`).
   Имя репозитория — `DZGenerator`, видимость — **Public**.
3. В блоке **Synchronization** включите «Activate synchronization» и укажите ветку
   `main`. Дальше всё, что приходит в `main` на GitHub, автоматически доезжает в
   SourceCraft: зеркало синхронизируется примерно раз в два часа, вручную — кнопкой
   **Sync now** на странице репозитория.
4. Убедитесь, что в основной ветке появился `.sourcecraft/sites.yaml` (он уже в
   репозитории):

   ```yaml
   site:
     root: "."
     ref: "main"
   ```

5. Через несколько минут сайт будет доступен по адресу
   `https://<слаг-организации>.sourcecraft.site/DZGenerator`, HTTPS — автоматически.

### Ограничения SourceCraft Sites (важные для нас)

- **Свой домен подключить нельзя.** Только `*.sourcecraft.site`.
- Сайт нельзя встраивать во `iframe` и нельзя использовать Service Worker
  (у нас их нет — ограничение нас не касается).
- Публикуется только из публичного репозитория публичной организации.
- Обновление после синка — «в течение нескольких минут», плюс задержка зеркала
  (до 2 часов). Для школьного сайта это нормально, но при правке перед уроком
  жмите **Sync now**.

### Вариант Б: публикация из ветки `release`

Если не хочется зависеть от расписания зеркала, сайт можно публиковать из отдельной
ветки того же репозитория:

```yaml
site:
  root: "."
  ref: "release"
```

Ветку `release` обновляйте одной командой после правок в `main`:

```bash
git push origin main:release
```

Плюс: содержимое сайта — точная копия `main`, а не «что успело синхронизироваться».
Минус: одна лишняя ветка и ручной шаг. Начните с зеркала `main` и переходите на
`release`, только если задержка синка начнёт мешать.

## 2. Свой домен: Object Storage + GitHub Actions

Нужен, когда адрес `*.sourcecraft.site` перестаёт устраивать: он попадает в письма
ученикам и в подписи. Домен регистрируется у любого регистратора (например, reg.ru),
дальше — Яндекс Облако.

### 2.1 Аккаунт и бакет

1. Создайте платёжный аккаунт Yandex Cloud (нужна карта; новым аккаунтам дают
   приветственный грант).
2. В консоли: **Object Storage → Создать бакет**. Имя бакета **точно совпадает с
   доменом**: `dz.example.ru` (точечное имя обязательно, иначе свой домен не
   подключить). Доступ — **Публичный**.
3. В бакете: **Настройки → Веб-сайт → Хостинг**, главная страница `index.html`.
   После этого сайт уже открывается по адресу `http://dz.example.ru.website.yandexcloud.net`.

### 2.2 Ключ для деплоя

```bash
yc iam service-account create --name dz-deploy
yc resource-manager folder add-access-binding <каталог> \
  --role storage.editor --subject serviceAccount:<id-сервисного-аккаунта>
yc iam access-key create --service-account-name dz-deploy
```

Последняя команда печатает `key_id` и `secret` — это статические ключи S3, они
показываются один раз.

### 2.3 Секреты в GitHub

**Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
|---|---|
| `YC_ACCESS_KEY_ID` | `key_id` из `yc iam access-key create` |
| `YC_SECRET_ACCESS_KEY` | `secret` оттуда же |
| `YC_BUCKET` | имя бакета, то есть домен: `dz.example.ru` |

После этого каждый пуш в `main` выкладывает сайт: `.github/workflows/deploy-yandex.yml`
синхронизирует репозиторий в бакет (`aws s3 sync --delete`). HTML отдаётся с
`must-revalidate` — номер версии в шапке меняется сразу после релиза; `.sb3`, картинки
и прочее кешируются на неделю. Файлы `.git`, `.github` и прошлых ревизий удаляются,
чтобы бакет не распухал. Пока секретов нет, workflow ничего не делает и не падает.

Ручной прогон без GitHub (проверить, что ключи рабочие):

```bash
export AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...
aws s3 sync . s3://dz.example.ru/ --delete \
  --endpoint-url https://storage.yandexcloud.net \
  --exclude ".git/*" --exclude ".github/*"
```

### 2.4 DNS

Проще всего взять **поддомен**: `dz.example.ru CNAME dz.example.ru.website.yandexcloud.net`
(запись CNAME допустима только для имени не ниже третьего уровня — как раз наш случай).

Корневой домен `example.ru` так подключить нельзя: нужна запись `ANAME`, а она есть
только в Cloud DNS. Тогда зона создаётся в Cloud DNS, а у регистратора
прописываются NS `ns1.yandexcloud.net` и `ns2.yandexcloud.net`. Cloud DNS
тарифицируется (в free tier — 1 млн запросов в месяц), поэтому ради одного
сайта проще поддомен.

### 2.5 HTTPS

1. **Certificate Manager → Сертификат от Let's Encrypt** на `dz.example.ru`.
2. Пройдите проверку прав на домен: сервис предложит CNAME/TXT-запись —
   добавьте её у регистратора (обычно 15–20 минут).
3. В бакете: **HTTPS → Настроить → Источник: Certificate Manager** → выберите
   сертификат.

Переадресация HTTP → HTTPS включается сама. Certificate Manager бесплатен,
продление сертификата Яндекс берёт на себя.

### 2.6 Адрес в коде и в старых письмах

```js
// V-labs-generator.html, строка 82
const SITE='https://dz.example.ru/';
```

После смены адреса:

- пересоберите страницы уроков: `node scripts/build-lessons.js`;
- письма, которые уже отправлены, содержат старый адрес — **не выключайте GitHub
  Pages**, пока они не устареют: старые ссылки на `.sb3` и страницы уроков должны
  продолжать открываться;
- строку `OLD_LESSON_LINK` (миграция черновиков версии до 1.7.0) не трогайте:
  она написана под старый адрес специально.

## 3. Когда понадобится база

База нужна ровно в тот момент, когда появляются три вещи: **личный кабинет
ученика**, **общий прогресс с нескольких устройств** и **сдача работ преподавателю**.
До этого хранилище — `localStorage` + JSON-копия, как сейчас.

Минимальная архитектура, которая переживёт рост:

```
ученик/преподаватель
        │  HTTPS
        ▼
Object Storage (статика: генератор, уроки, .sb3)
        │  fetch
        ▼
API Gateway ──► Cloud Functions (Node/Python, без сервера)
                     │
                     ├── YDB Serverless  (или Managed PostgreSQL)
                     └── Object Storage, приватный бакет (работы учеников)
```

Что это даёт и сколько стоит:

- **Cloud Functions** — 1 млн вызовов и 10 ГБ·час в месяц бесплатно, дальше
  копейки. Функция на 200 строк закрывает весь API кабинета.
- **YDB Serverless** — 1 млн Request Units и 1 ГБ бесплатно; платите только за
  запросы, простоя нет. Для «профиль + черновик + история» хватает с запасом.
- **Managed PostgreSQL** — берите, если нужны SQL-отчёты, JOIN'ы и привычные
  инструменты: минимальный кластер — от ~1 700–2 000 ₽/мес (burstable 1 vCPU,
  2 ГБ RAM, 10 ГБ SSD; точную сумму даёт калькулятор Yandex Cloud).
- **Файлы** (`.sb3` ученика) — в приватный бакет, отдавать через подписанные
  ссылки на время; публичным бакет держать не нужно.

Что хранить в базе (повторяет то, что уже есть в `localStorage`, и поэтому
переезд будет дешёвым): профили, черновик письма, историю писем, настройки,
отметки «урок пройден». Схема — одна таблица `students` и одна `documents`
с JSON-полем; нормализовать до уроков/заданий стоит только когда появятся
отчёты по курсу.

### Важно: персональные данные

Как только в базе появятся имена детей, это персональные данные по 152-ФЗ:

- хранение — в России (Yandex Cloud подходит);
- нужно уведомление в Роскомнадзор об обработке ПДн и согласия родителей;
- минимальный набор: имя, класс, код ученика. Фамилию, телефон и почту ребёнка
  не собирайте, пока без них можно обойтись; вход — по коду, который выдаёт
  преподаватель, а не по e-mail ребёнка.

Поэтому базу стоит заводить сразу «правильно», а не как эксперимент на живых данных.

## 4. Порядок действий

1. **Сегодня:** подключить SourceCraft Sites (раздел 1), проверить сайт по чек-листу

3. **Когда появится кабинет:** функции + YDB/Postgres (раздел 3), сначала на одном
   классе, с согласиями родителей.
